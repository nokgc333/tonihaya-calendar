## 0. ズーム階層での位置づけ

Google Calendar に沿った 年→月→週→日 の4段階。本設計は最下層 L3。

| レベル | 内容 | 状態 |
|--------|------|------|
| L0 | 年間 overview（12ヶ月俯瞰） | 実装済み |
| L1 | 月間 overview（単月） | 実装済み |
| L2 | 週間 overview（Google週表示） | 実装済み |
| **L3** | **日間 overview（Google日表示）** | **本設計** |

## 1. 目的とスコープ

L2（週）から日をドリルダウンし、その日を Google Calendar 風の時間グリッドで表示する。イベント（予定）は将来機能のため、MVP では**単一日の時間グリッド骨格**（時間軸×1日・大きな日付ヘッダー・終日行・現在時刻ライン）を**中央寄せの単カラム**で表示する。

**対象**: L2 ↔ L3。
**対象外（YAGNI）**: イベント/予定の表示・作成、六曜、ドラッグ操作、サイド情報パネル。

**方針**: 安定稼働中の L2（`WeekView` / 99テスト緑）は凍結し、L3 を独立コンポーネント＋小さなドメイン関数として追加する（A案）。グリッド描画の重複は将来 `/simplify` で共通部品化し得るが、本増分では早期抽象化しない。

## 2. 状態モデルとURL

`src/domain/view/zoom.ts` は既に `level:"day"` 型を持ち、`parseZoom` / `zoomToQuery` は `v=day` を相互変換できる（L2実装時に予約済み）。**本増分での zoom.ts 変更は不要**。

| URL | レベル |
|-----|--------|
| `/?y=2026&m=7&d=5&v=week` | week（7/5 を含む週） |
| `/?y=2026&m=7&d=5&v=day` | day（7/5） |

- `d` は対象日、`v=day` で日ビューを区別する。年は 1950–2150 にクランプ（既存）。

## 3. 入口・戻り・日送り

- **入口（L2→L3）**: `WeekView` の以下いずれかのクリックで `navigate({level:"day", year, month, day}, "push")`。
  - ① 日ヘッダー（曜日＋日付）
  - ② 時間グリッドの各日カラム
  - ズームのピボット共有要素は**その日の列**1要素に集約する（両操作とも同じ列がモーフ起点）。
- **戻り（L3→L2）**: `‹ 戻る` ボタン ／ `ESC` ／ ブラウザ戻る → その日を含む週の L2 へ。
  - 週は日から一意に決まるため、L2 の `weekOrigin` に相当する文脈保持は不要。`navigate({level:"week", 同じ year/month/day}, "push")` でよい。
- **日送り**: L2 の前週/次週に倣い、`‹ 日付 ›`（前日/翌日）ボタンで `replace` 遷移（epochDay ±1）。

## 4. 日ビューのレイアウト（Google風骨組み・中央寄せ単カラム）

```
        ┌───────────────────────────────────┐
        │ ‹戻る    ‹ 2026年7月5日(日) ›        │  ← ナビ（前日/次日）
        ├───────────────────────────────────┤
        │ 2026年7月5日（日）  [祝日名]         │  ← 大きな日付ヘッダー
        ├──────┬────────────────────────────┤
        │ 終日 │ [祝日/週末の帯]              │  ← 終日行
        ├──────┼────────────────────────────┤
        │ 0時  │ ┆                           │  ← 時間×1日グリッド
        │ 1時  │ ┄┄┄┄ 今 ━━━━━━━━━━┄┄┄ (今ライン)│    （0〜23時・内部スクロール）
        │ …   │                             │
        │ 23時 │                             │
        └──────┴────────────────────────────┘
   （外側 max-w-2xl 相当で中央寄せ）
```

- **中央寄せ**: 外側ラッパーで読みやすい幅（例 `max-w-2xl mx-auto`）に制限。L0/L1/L2 の最大幅規約と調和。
- **時間軸（左列）**: 0〜23 時のラベル（`3.5rem`）。
- **日付ヘッダー**: 「2026年7月5日（日）」を大きく表示。曜日・祝日は既存トークンで着色（日祝=赤、土=水色）。祝日ならヘッダーに祝日名を併記。
- **終日行**: 祝日名の帯（`border-strong` 上下枠）。イベントは将来。
- **本体グリッド**: 横線=毎時の区切りの単カラム。`HOUR_HEIGHT = 48px`、本体は**内部縦スクロール**。今日のときのみ入場時に**現在時刻付近へ自動スクロール**。
- **今ライン**: その日が今日なら現在時刻（client の時:分）の水平線（`accent-red`）。
- **週開始設定**: 日ビューは単日のため無関係。

## 5. ドメイン（TDD）

`src/domain/view/dayView.ts`:

```
buildDayView(year, month, day, today: CivilDate | null): DayViewModel
// DayViewModel = { day: WeekDay }
```

- 既存 `WeekDay`（`year`/`month`/`day`/`weekday`/`isToday`/`isHoliday`/`holidayName?`/`isSaturday`/`isSunday`）を1件生成。
- 祝日は `getHoliday`、曜日は `weekdayOf`、`isToday` は today と一致判定。
- 「今ライン」の縦位置は既存 `minutesToOffset(minutes, hourHeightPx)` を再利用。
- 純粋関数・テスト（平日/土/日/祝日/today一致・today不一致/today=null）。

## 6. コンポーネント構成

```
CalendarApp
 └─ level 分岐:
     overview → OverviewBody（L0）
     month    → MonthDetail（L1）
     week     → WeekView（L2）※日ヘッダー/列に onDayOpen 追加
     day      → DayView（新・L3）
```

- `DayView`（新）: ナビ（戻る/前日/次日）＋大きな日付ヘッダー＋終日行＋時間グリッド＋今ライン。内部スクロール。`WeekView` の時間グリッド構造（`HOUR_HEIGHT` / `minutesToOffset` / 自動スクロール / 現在時刻ライン / ESC戻る）を1カラム版に写す。
- `WeekView`（既存）: 日ヘッダーと各日カラムに `onDayOpen(year, month, day)` を配線（新規 prop）。
- `CalendarApp`: `zoom.level === "day"` 分岐を追加（week 分岐と同構造：`h-dvh` フレックス＋`TodayHeader`＋中央ラッパー＋`DayView`）。

## 7. 遷移（View Transitions・ピボット流用）

- L1⇄L2 と対称な L2⇄L3 のピボット機構を `CalendarApp` に追加。
- 共有要素名は L1⇄L2 の `day-zoom` と**衝突しない別名**（例 `hour-zoom`）。
- 前進（L2→L3）: 押した日の**列**に `flushSync` で `viewTransitionName:"hour-zoom"` を付与 → L3 外枠の同名要素とモーフ。後退（L3→L2）はピボット保持で対称。
- reduced-motion / 非対応は即時フォールバック（既存 `withTransition` = `document.startViewTransition(() => flushSync(commit))` がそのまま担保）。
- **既知の懸念**: L2 外枠は L1 へ戻る用に `day-zoom` を保持している。L2→L3 遷移時、外枠の `day-zoom` が新DOM(L3)側に対応先を持たず、外枠全体が1スナップショット化してモーフを乱す可能性がある。対処候補は「L2→L3 遷移直前に外枠の `day-zoom` を一時的に外す」。**設計目標は「列→L3外枠のモーフ」とし、細部は実装フェーズで DOM 検証しながら調整する**。
- 共有要素名は **1ビュー内で1要素のみ**（複数付与は無効・衝突）の原則を厳守。

## 8. レスポンシブ

- 中央寄せ単カラムのため横スクロール要件は L2 より緩い。時間軸左列＋単一日カラムが狭幅でも収まるよう最小幅を確保。
- 極小画面（<375px 未満）は既存方針どおり切り捨て（`min-w-[375px]`）。
