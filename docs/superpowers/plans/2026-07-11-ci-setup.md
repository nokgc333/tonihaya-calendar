# CI導入（GitHub Actions＋LHCI速度ガード） Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 変更ごとに正しさ（型・テスト・ビルド）と速度（バンドルサイズ回帰）を GitHub Actions で自動検証する CI を導入する。

**Architecture:** 1ワークフロー `ci.yml`／2ジョブ。`verify`（type-check→test→build→`out/` を artifact 化・ブロッキング）と `lighthouse`（`needs: verify`・LHCI で `out/` を計測。サイズ予算=error / スコア=warn）。予算はローカル実測ベースライン×1.15（ガードレール）。

**Tech Stack:** GitHub Actions（checkout/setup-node/upload-artifact/download-artifact @v4）／`@lhci/cli`（LHCI・staticDistDir で自前静的配信）／Next.js static export（`output: "export"` → `out/`）／npm。

## Global Constraints

- コミット: `type: 日本語説明`（命令形・先頭小文字の英語型名・末尾ピリオドなし）、**`Co-Authored-By` なし**、1意味単位=1コミット。ブランチは既存の **`chore/ci`**（develop から。完了後 `--no-ff` で develop へ）。
- `npm run dev` はフックでブロック。手元の3点セット: `npx vitest run && npx tsc --noEmit && npx next build`。
- Node: `engines.node >=22`。**CI・`.nvmrc` ともに `22`** に統一（手元は 24 だが下限 LTS の 22 に合わせる）。
- package.json は `type: module`。LHCI 設定は **`.lighthouserc.cjs`（CommonJS）** で書く（`.js` だと ESM 扱いで `module.exports` が壊れるため。かつコメントで実測ベースラインを残せる）。
- lint は CI に含めない（ESLint 未導入。別タスク `chore/eslint-setup`）。
- 速度予算は **ガードレール = 実測ベースライン×1.15**（案①）。ブロッキングは `resource-summary:script:size`（主）と `resource-summary:total:size`（副）。Performance スコアは **warn**（非ブロッキング）。
- 設計書: `docs/superpowers/specs/2026-07-11-ci-setup-design.md`。

- **Modify** `package.json` — `devDependencies` に `@lhci/cli` 追加、`scripts` に `"ci:lhci": "lhci autorun"` 追加。
- **Create** `.lighthouserc.cjs` — LHCI 設定（staticDistDir=out / numberOfRuns=3 / サイズ予算 error・スコア warn / upload=temporary-public-storage）。実測ベースラインをコメントで保持。

タスクは2つ。**Task 1** は完全にローカルで検証できる（LHCI 設定＋予算測定）。**Task 2** はワークフローで、PR を開いて実挙動で検証する。

## Task 1: LHCI 設定と速度予算の測定

**Files:**
- Modify: `package.json`（`devDependencies`・`scripts`）
- Create: `.lighthouserc.cjs`
- Modify: `.gitignore`

**Interfaces:**
- Produces: リポジトリ直下に LHCI 設定 `.lighthouserc.cjs`（`lhci autorun` が自動検出）。`npm run ci:lhci` で collect→assert→upload を実行。Task 2 の `lighthouse` ジョブはこの設定と script を使う。
- Consumes: `npm run build` が生成する `out/`（既存・`output: "export"`）。

- [ ] **Step 1: `@lhci/cli` を devDependency として追加**

```bash
npm install -D @lhci/cli
```

期待: `package.json` の `devDependencies` に `@lhci/cli` が入り、`package-lock.json` が更新される。

- [ ] **Step 2: 本番相当の静的出力を生成**

```bash
npm run build
```

期待: `out/` が生成される（`✓ Exporting`）。

- [ ] **Step 3: ベースライン転送量を1回計測**

```bash
npx lhci collect --staticDistDir=./out --numberOfRuns=1
```

期待: `.lighthouseci/` に `lhr-*.json` が出力される（LHCI が自前でローカル配信して計測）。Chrome が見つからない場合は環境変数 `CHROME_PATH` を設定。

- [ ] **Step 4: script/total の実測転送バイトを取り出す**

```bash
node -e "const fs=require('fs');const d='.lighthouseci';const f=fs.readdirSync(d).filter(x=>x.startsWith('lhr-')).map(x=>d+'/'+x).sort();const lhr=JSON.parse(fs.readFileSync(f[f.length-1]));const items=lhr.audits['resource-summary'].details.items;const g=t=>items.find(i=>i.resourceType===t)?.transferSize||0;const s=g('script'),t=g('total');console.log('script bytes =',s,'-> budget',Math.ceil(s*1.15/1024)*1024);console.log('total  bytes =',t,'-> budget',Math.ceil(t*1.15/1024)*1024);"
```

期待: `script bytes = ... -> budget <SCRIPT_BUDGET>` と `total bytes = ... -> budget <TOTAL_BUDGET>` の2行が出る。この2つの budget 値（×1.15 を 1KB 単位で切り上げ）を次のステップで使う。**実測値と budget をメモしておく**（コメントに残す）。

- [ ] **Step 5: `.lighthouserc.cjs` を作成**

`<SCRIPT_BUDGET>` / `<TOTAL_BUDGET>` は Step 4 の出力値に、`<SCRIPT_BASE>` / `<TOTAL_BASE>` は実測バイトに、`<DATE>` は当日（2026-07-11）に置き換える。

```js
// tonihaya-calendar LHCI 設定（PR/CI の速度ガード）。
// 速度予算は「実測ベースライン × 1.15」のガードレール（設計書 §5・案①）。
// ベースライン実測（out/ 転送バイト・<DATE> 計測）:
//   script(total JS transfer) = <SCRIPT_BASE> B  -> budget <SCRIPT_BUDGET> B
//   total (page transfer)     = <TOTAL_BASE>  B  -> budget <TOTAL_BUDGET>  B
// 予算を引き上げる場合は同一 PR でこの値を明示更新すること（肥大化を履歴に残す）。
module.exports = {
  ci: {
    collect: {
      staticDistDir: "out", // LHCI が out/ を自前で静的配信（別途 http サーバ不要）
      numberOfRuns: 3, // 中央値でランナーのノイズを低減（モバイル既定エミュレーション）
    },
    assert: {
      assertions: {
        "resource-summary:script:size": ["error", { maxNumericValue: <SCRIPT_BUDGET> }],
        "resource-summary:total:size": ["error", { maxNumericValue: <TOTAL_BUDGET> }],
        "categories:performance": ["warn", { minScore: 0.9 }],
      },
    },
    upload: {
      target: "temporary-public-storage", // ログに共有レポート URL を出す
    },
  },
};
```

- [ ] **Step 6: `package.json` に `ci:lhci` script を追加**

`scripts` に次を追加（`lighthouse` script の隣）:

```json
"ci:lhci": "lhci autorun"
```

- [ ] **Step 7: `.gitignore` に LHCI 作業ディレクトリを追記**

`.gitignore` 末尾の「# Lighthouse レポート出力」ブロックを次にする:

```
# Lighthouse レポート出力
.lighthouse/
.lighthouseci/
```

- [ ] **Step 8: ローカルで assert が通ることを検証**

```bash
npm run build && npm run ci:lhci
```

期待:
- `resource-summary:script:size` と `resource-summary:total:size` が **PASS**（現ベースラインは予算内）。
- `categories:performance` は warn 表示のみ（**ジョブは失敗しない**）。
- 末尾に `temporary-public-storage` の共有レポート URL が出る。
- 終了コード 0。

もし assert が fail する場合は予算計算（Step 4/5）を見直す。

- [ ] **Step 9: コミット**

```bash
git add package.json package-lock.json .lighthouserc.cjs .gitignore
git commit -m "chore: LHCIの速度予算ガードを追加"
```

## Task 2: GitHub Actions ワークフローと Node ピン

**Files:**
- Create: `.nvmrc`
- Create: `.github/workflows/ci.yml`

**Interfaces:**
- Consumes: Task 1 の `.lighthouserc.cjs` と `npm run ci:lhci`、既存 scripts（`type-check`/`test`/`build`）、`out/`。
- Produces: PR/develop/main push で走る CI。`verify` が `out/` artifact を上げ、`lighthouse` が受け取って計測する。

- [ ] **Step 1: `.nvmrc` を作成**

```
22
```

- [ ] **Step 2: `.github/workflows/ci.yml` を作成**

```yaml
name: CI

on:
  pull_request:
    branches: [develop, main]
  push:
    branches: [develop, main]

concurrency:
  group: ci-${{ github.ref }}
  cancel-in-progress: true

jobs:
  verify:
    name: verify (type-check / test / build)
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with:
          node-version-file: .nvmrc
          cache: npm
      - run: npm ci
      - run: npm run type-check
      - run: npm run test
      - run: npm run build
      - uses: actions/upload-artifact@v4
        with:
          name: out
          path: out/
          retention-days: 1

  lighthouse:
    name: lighthouse (size budget / perf score)
    needs: verify
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with:
          node-version-file: .nvmrc
          cache: npm
      - run: npm ci
      - uses: actions/download-artifact@v4
        with:
          name: out
          path: out/
      - run: npm run ci:lhci
```

- [ ] **Step 3: コミット**

```bash
git add .nvmrc .github/workflows/ci.yml
git commit -m "chore: 正しさ+速度を検証するCIワークフローを追加"
```

- [ ] **Step 4: ブランチを push して PR を開く**

```bash
git push -u origin chore/ci
gh pr create --base develop --head chore/ci \
  --title "chore: CI導入（正しさ+速度ガード）" \
  --body "型/テスト/ビルドの verify と LHCI 速度ガードを追加。設計: docs/superpowers/specs/2026-07-11-ci-setup-design.md"
```

- [ ] **Step 5: 両ジョブが緑になることを確認**

```bash
gh pr checks --watch
```

期待: `verify` と `lighthouse` の両チェックが **pass（緑）**。`lighthouse` のログに共有レポート URL と perf の warn が出る。

- [ ] **Step 6: 速度ゲートが実際にブロックすることを実証（重い import を一時投入）**

`src/app/page.tsx`（または任意のクライアント読込コンポーネント）先頭に、意図的に重い依存を一時追加する。例として既存の重量級を避け、確実にバイトを増やすダミー:

```bash
# 一時的に大きなJSを混ぜる（例: moment を入れて import）
npm install moment
```

`src/components/CalendarApp.tsx` の先頭 import 群の末尾に一時的に追加:

```ts
import moment from "moment";
// 一時: バンドルに載せるための参照（ツリーシェイク回避）
if (typeof window !== "undefined") console.log(moment().toISOString());
```

コミットして push:

```bash
git add -A && git commit -m "test: 速度ゲート検証用に一時的に重い依存を投入"
git push
gh pr checks --watch
```

期待: `verify` は緑のまま、**`lighthouse` が赤**（`resource-summary:script:size` が予算超過で error）。

- [ ] **Step 7: 検証用コミットを履歴ごと落として緑復帰を確認**

develop に検証ノイズを残さないため、revert ではなく **reset で Step 6 のコミットを消す**（feature ブランチなので force-with-lease 可）。Step 6 のコミットは HEAD、その1つ前が「CIワークフローを追加」コミット:

```bash
git reset --hard HEAD~1          # moment 投入コミットを丸ごと破棄
git push --force-with-lease
gh pr checks --watch
```

期待: PR から検証コミットが消え、`lighthouse` が **緑に復帰**。これで「予算超過で赤／解消で緑」が実証できた。

> 確認: `git log --oneline develop..chore/ci` に `moment` 関連コミットが無く、`git diff develop -- package.json` に `moment` が出ないこと。ローカル `node_modules` の moment は無視されるので放置で可（次の `npm ci` で消える）。

- [ ] **Step 8: develop へ統合**

PR チェックが緑であることを確認後、既存フロー（ローカル `--no-ff` マージ）で develop へ入れる:

```bash
git switch develop
git merge --no-ff chore/ci -m "Merge branch 'chore/ci' into develop"
git push origin develop
gh pr view chore/ci --json state  # PR は develop push 取り込みで閉じる場合あり。開いたままなら gh pr close でも可
```

期待: develop への push で CI（`push: [develop]`）が再度走り緑。以後の全 PR で verify+lighthouse が自動実行される。

- [ ] **Step 9: 一時ブランチを掃除**

```bash
git branch -d chore/ci
```
