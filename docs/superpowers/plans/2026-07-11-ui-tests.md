# UIテスト拡充（components / hooks 要所・C-3） Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `src/components`・`src/hooks`（現状テストゼロ）の高価値4ユニットにコンポーネント/フックテストを導入し、CI で自動実行する。

**Architecture:** happy-dom＋@testing-library で UI 層のみ DOM テスト。vitest は `environmentMatchGlobs` で `components/**`・`hooks/**` を happy-dom、domain は `node` のまま高速維持。既存コードは正しく動いているので、各テストは「既存挙動を固定する回帰テスト」＝書いたら **GREEN（PASS）になる**のが期待値（RED を作る通常 TDD とは逆。もし想定外に FAIL したらテストのバグか実バグなので systematic-debugging で調べる）。

**Tech Stack:** Vitest 3（globals）／happy-dom 20／@testing-library/react 16（React 19 対応）／@testing-library/user-event／@testing-library/jest-dom。

## Global Constraints

- コミット: `type: 日本語説明`（命令形・先頭小文字の英語型名・末尾ピリオドなし）、**`Co-Authored-By` なし**、1意味単位=1コミット。ブランチは既存の **`test/ui-components`**（develop から。完了後 `--no-ff` で develop へ）。
- `npm run dev` はフックでブロック。3点セット: `npx vitest run && npx tsc --noEmit && npx next build`。
- **coverage 対象は `src/domain/**` のまま据え置く**（UI 層に閾値を課さない）。
- クエリは role/text ベース（`getByRole`/`getByText`/`getByLabelText`）中心。非セマンティックなドットのみ container クエリを許容。
- テスト名は日本語・AAA（Arrange/Act/Assert）。非同期は `findBy*`/`waitFor`/`await` で待つ。
- 色・値のハードコード比較はしない（`eventColor` は CSS 変数文字列を返すため色検証はしない）。
- 対象コンポーネントの実 props（確認済み）:
  - `EventChip({ event, onSelect? })`
  - `EventModal({ initial, defaultDate, onSubmit, onDelete?, onClose })`（保存ボタン名「保存」・削除ボタン名「削除」・タイトル label「タイトル」・終日 checkbox・エラーは `・{message}` の `<li>`・削除は `window.confirm` 経由）
  - `MonthCard({ month, weekStart, size, spacious, year, events, onEventSelect, ... })`
  - `EventProvider({ children, repository? })` / `useEvents()` → `{ events, loading, addEvent, updateEvent, removeEvent }`
- `validateEvent` のエラーメッセージ（実装と一致させる）: `タイトルを入力してください` / `URLは http/https のみ使用できます` / `終了日は開始日以降にしてください` / `時間イベントは開始・終了時刻が必要です` / `終了時刻は開始時刻より後にしてください`
- `buildMonthView(year, month, today, weekStart)` → `MonthView`（第4引数は `WeekStart` 文字列）。
- 設計書: `docs/superpowers/specs/2026-07-11-ui-tests-design.md`。

```ts
import "@testing-library/jest-dom/vitest";

// setupFiles は node 環境の domain テストでも走るため document 参照を typeof でガードする。
// happy-dom/jsdom は View Transitions API を未実装なので、触れても落ちないよう即時実行フォールバックを置く。
if (typeof document !== "undefined" && !("startViewTransition" in document)) {
  // @ts-expect-error 実験的 API のテスト用モック
  document.startViewTransition = (cb: () => void) => {
    cb();
    return {
      finished: Promise.resolve(),
      ready: Promise.resolve(),
      updateCallbackDone: Promise.resolve(),
    };
  };
}

// useEvents の addEvent が使う crypto.randomUUID を、無い環境向けに簡易フォールバック。
if (typeof globalThis.crypto === "undefined" || typeof globalThis.crypto.randomUUID !== "function") {
  const g = globalThis as unknown as { crypto: { randomUUID: () => string } };
  g.crypto = {
    ...(globalThis.crypto ?? {}),
    randomUUID: () => "test-" + Math.random().toString(16).slice(2),
  } as typeof g.crypto;
}
```

**Interfaces:**

- [ ] **Step 1: `src/hooks/useEvents.test.tsx` を作成**

```tsx
import { render, screen, waitFor } from "@testing-library/react";
import userEvent from "@testing-library/user-event";
import { describe, it, expect } from "vitest";
import { EventProvider, useEvents } from "@/hooks/useEvents";
import type { EventRepository } from "@/data/eventRepository";
import type { CalendarEvent, EventDraft } from "@/domain/event";

// 注入用の in-memory リポジトリ（localStorage に依存しない＝決定論的）。
class FakeRepo implements EventRepository {
  store: CalendarEvent[];
  constructor(seed: CalendarEvent[] = []) {
    this.store = [...seed];
  }
  async list() {
    return [...this.store];
  }
  async add(e: CalendarEvent) {
    this.store.push(e);
  }
  async update(e: CalendarEvent) {
    this.store = this.store.map((x) => (x.id === e.id ? e : x));
  }
  async remove(id: string) {
    this.store = this.store.filter((x) => x.id !== id);
  }
}

// add が必ず失敗するリポジトリ（error path 用）。
class ThrowingAddRepo extends FakeRepo {
  async add(): Promise<void> {
    throw new Error("save failed");
  }
}

const draft = (title: string): EventDraft => ({
  title,
  allDay: true,
  start: { date: { year: 2026, month: 7, day: 11 } },
  end: { date: { year: 2026, month: 7, day: 11 } },
  colorKey: "blue",
  priority: "normal",
});

const seeded = (title: string): CalendarEvent => ({
  ...draft(title),
  id: "seed-" + title,
  createdAt: 0,
  updatedAt: 0,
});

// useEvents を読み、操作ボタンと状態を露出する検証用ハーネス。
function Harness() {
  const { events, loading, addEvent, updateEvent, removeEvent } = useEvents();
  return (
    <div>
      <span data-testid="loading">{String(loading)}</span>
      <span data-testid="count">{events.length}</span>
      <span data-testid="titles">{events.map((e) => e.title).join(",")}</span>
      <button onClick={() => addEvent(draft("新規"))}>add</button>
      <button onClick={() => events[0] && updateEvent({ ...events[0], title: "更新後" })}>update</button>
      <button onClick={() => events[0] && removeEvent(events[0].id)}>remove</button>
    </div>
  );
}

const renderWith = (repo: EventRepository) =>
  render(
    <EventProvider repository={repo}>
      <Harness />
    </EventProvider>,
  );

describe("useEvents", () => {
  it("初期化時にリポジトリの一覧を読み込み loading を解除する", async () => {
    renderWith(new FakeRepo([seeded("A")]));
    await waitFor(() => expect(screen.getByTestId("loading")).toHaveTextContent("false"));
    expect(screen.getByTestId("count")).toHaveTextContent("1");
  });

  it("addEvent で楽観更新しリポジトリにも保存される", async () => {
    const repo = new FakeRepo();
    const user = userEvent.setup();
    renderWith(repo);
    await waitFor(() => expect(screen.getByTestId("loading")).toHaveTextContent("false"));
    await user.click(screen.getByRole("button", { name: "add" }));
    await waitFor(() => expect(screen.getByTestId("count")).toHaveTextContent("1"));
    expect(repo.store).toHaveLength(1);
    expect(repo.store[0].id).toBeTruthy();
```
