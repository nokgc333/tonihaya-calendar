### レベル遷移の高速化（globals.css / View Transitions）
- `::view-transition-old/new(root)` = **200ms**、`::view-transition-group(day-zoom/hour-zoom/jump-zoom)` = **200ms明示固定**（UA既定約250msが体感尺を支配していたのを是正）、ズーム元 old(day/hour-zoom) = **100ms**先行フェード。
- **delay（オーバーラップで「縮む→現れる」順序感）は導入見送り（速度優先で意図的に不採用）**。`new(root)` に `animation-delay: 60〜90ms` を足す案は、遷移の総時間をその分だけ**伸ばす**（＝体感がわずかに遅くなる）ため、「とにかく速い」の軸に反する。現行の動き（root 200ms＋group 200ms固定＋ズーム元 100ms 先行フェード）で確定・満足。将来この結論を覆すには「速度低下を上回る演出価値」の根拠が要る。

### 堅牢化B（リリース前の仕上げ）
1. **中1**: URLを編集モーダルで安全リンク化（描画時も `isSafeUrl` 再検証＋`rel="noopener noreferrer"`、`javascript:`は非表示）。
2. **中2**: 読込に型ガード `isStoredCalendarEvent` を通し破損要素を除外（1件破損で全体クラッシュを防止）。
3. **低3**: `write()` の `setItem` を try/catch＋開発ログ＋再throw、`useEvents` は保存成功時のみ楽観更新。

## 5. 落とし穴メモ（再発防止）

- ローカル `next build` と Vercel はJSチャンクhashが必ず異なる。挙動不変の変更は出力で新旧判別不可。
- zsh では `status` は read-only 予約変数（スクリプトで変数名に使わない）。
- `vercel inspect`（現行CLI）は commit SHA を出さない → デプロイ同一性は「push直後のProduction Readyエイリアス紐付き＋本番実機」で確認。
